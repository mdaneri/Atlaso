Atlaso documentation¶

Atlaso brings infrastructure, storage, identity, networking, and lifecycle workflows together for virtualization proof-of-concept, lab, and test environments.

Choose your path¶

  • Getting started for installation and first configuration.
  • Operate for daily appliance tasks, changes, updates, automation, and troubleshooting.
  • Services for DNS, identity, storage, network boot, VCF/ESX password vaults, and VCF integrations.
  • Reference for APIs, image building, interoperability, and detailed technical behavior.
  • Contribute for repository workflow, documentation, design, and implementation policies.
  • Project for the Atlaso name, branding, roadmaps, and historical design records.

Latest documentation: This site describes the latest supported Atlaso release. Pages marked Roadmap or Historical are context, not statements of current appliance behavior.

Popular guides¶

Start with these common operator tasks. The section indexes above contain the complete guide set.

  • Recover management access — correct management networking from the local console.
  • Use the Atlaso API — create scoped tokens and call the versioned REST contract safely.
  • Update the appliance — review update sources and install signed updates.
  • Configure DNS — manage appliance name resolution and authoritative zones.
  • Prepare Network Boot — discover hosts and stage interactive or scripted boot workflows.
  • Manage credentials with Vaults — scope encrypted VCF and ESX credentials to approved workflows.
  • Configure OpenID Connect — manage clients, identity sources, claims, and key rotation.
  • Explore experimental vSphere Key Providers — review the unverified candidate VCF 9.1 contract and its acceptance gate.

Safety boundary¶

Development appliances keep system adapters in dry-run mode by default. Desired-state editing does not mutate the host. Operators explicitly review and submit selected valid units through the global appliance-change workflow.
